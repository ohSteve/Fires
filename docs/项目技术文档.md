### 1.3 架构设计

#### 导航方案

采用**状态驱动**导航，不依赖 Jetpack Navigation Compose：

```kotlin
sealed class Screen {
    data object GoalList : Screen()           // 主页面（含底部4栏）
    data class GoalDetail(val goalId: Long) : Screen()  // 目标详情
    data object MyCheckIn : Screen()          // 打卡项目管理
    data object Settings : Screen()           // 设置
}
```

`MainActivity` 持有 `currentScreen: Screen` 的 `mutableStateOf`，通过 `when` 分支渲染不同页面。切换 `currentScreen` 即完成导航。此方案的优点是无额外依赖，回退栈简单（最多一层深度），不会积累内存。

#### MVVM 数据流

```
用户交互 → Composable UI
              ↕ (StateFlow collectAsState)
         ViewModel (AndroidViewModel)
              ↕ (suspend / Flow)
         Room DAO
              ↕
         SQLite 数据库
```

- **ViewModel** 通过 `(application as TodoApplication).database` 获取数据库实例
- 所有数据库操作均在 `viewModelScope.launch` 中异步执行
- DAO 返回 `Flow<T>` 的数据通过 `stateIn(WhileSubscribed(5000))` 转为 `StateFlow`，Compose 通过 `collectAsState()` 订阅

#### 数据库设计

6 张表，版本 10：

| 表名 | 主键 | 外键 | 用途 |
|------|------|------|------|
| `goals` | id（自增） | — | 目标定义 |
| `milestones` | id（自增） | goalId → goals.id (CASCADE) | 目标下的里程碑 |
| `todo_items` | id（自增） | — | 待办事项 |
| `journals` | date（字符串日期） | — | 每日日志 |
| `checkin_items` | id（自增） | — | 打卡项目定义 |
| `checkin_records` | id（自增） | itemId（逻辑引用 checkin_items） | 每日打卡记录 |

MilestoneEntity 是唯一有显式外键的表，`onDelete = CASCADE` 保证删除目标时自动清除里程碑。

#### 权限声明

| 权限 | 用途 |
|------|------|
| `PACKAGE_USAGE_STATS` | 读取手机使用时长（日志页） |
| `POST_NOTIFICATIONS` | Android 13+ 通知权限 |
| `RECEIVE_BOOT_COMPLETED` | 开机后恢复闹钟 |

`<queries>` 块声明 `MAIN` intent 以查询已安装应用名称。

**不声明** `INTERNET` 权限，应用完全离线。

### 1.4 安全设计

- **数据存储**：Room 数据库文件位于 App 私有目录，其他 App 不可访问
- **备份策略**：`allowBackup="false"`，数据不自动上传云端
- **数据库升级**：当前版本 10。若 Entity 不变则无需升版本，覆盖安装数据完整保留。若需加字段，须编写 `Migration(10, 11)` 对象
- **导出导入**：`DataMigration` 支持 SQLite 格式（换手机用）和 TSV 格式（数据分析用）。导入前自动备份旧库，写入后校验 SQLite 文件有效性，失败时还原备份

## 二、开发历程

### 2.1 项目演进路线

| 阶段 | 主要内容 |
|------|---------|
| **起步** | 从简单的 Todo App 模板开始，建立 Kotlin + Compose + Room 基础架构 |
| **目标栏** | 实现目标 CRUD、DDL 排序、实现/撤销目标、里程碑时间轴、里程碑编辑弹窗 |
| **打卡栏** | 打卡项目定义（每天/周定期）、每日打卡记录生成、完成/放弃/撤销、周期管理、补卡功能 |
| **待办栏** | 待办 CRUD、DDL 颜色三态（未来/当天/过期）、月度筛选、完成折叠、长按编辑 |
| **日志栏** | 自动汇总（目标+打卡+待办）、笔记/娱乐输入、及时满足型娱乐选项、手机使用时长 Top 5、下拉刷新 |
| **设置页** | 浅色/深色主题、6 种主题色+自定义色号、每日提醒（时间+自定义文字+状态栏通知）、数据导出/导入 |
| **生产就绪** | 消除 `!!` 强制解引用、清理死代码、统一颜色系统、修复自动放弃逻辑一致性、数据库常量化、导入备份还原 |

### 2.2 关键设计决策

1. **不用 Hilt/Koin**：项目规模适中，手动单例模式足够清晰，避免引入额外的 DI 框架复杂度
2. **不用 Navigation Compose**：只有 4 个页面，sealed class + `when` 分支比 NavHost 更直观，且无回退栈管理负担
3. **补卡功能**：打卡项目和每日记录分离（`CheckInItemEntity` vs `CheckInRecordEntity`），补卡是在当天为已有项目创建一条独立记录（`isBackfill = true`），不改变项目的周期定义
4. **日志自动汇总**：打开过期日志时自动将 pending 打卡转为 abandoned，确保历史数据准确
5. **闹钟选 `set()` 而非 `setExact()`**：避免 `SCHEDULE_EXACT_ALARM` 权限的用户手动授权步骤，每日提醒场景分钟级误差可接受

## 三、功能介绍与使用指南

### 3.1 底部导航

App 底部有四个标签页，打开默认进入"目标"栏：

| 标签 | 图标 | 功能 |
|------|------|------|
| 目标 | 🚩 | 管理长期目标，设置 DDL 和里程碑 |
| 打卡 | 🔔 | 每日打卡，追踪习惯 |
| 待办 | ✅ | 待办事项，DDL 提醒 |
| 日志 | 📖 | 每日自动汇总 + 手动笔记 |

### 3.2 目标栏

**创建目标**：点击右下角 `+` → 输入目标名称 → 可选设置 DDL（截止日期）。

**目标列表**：按 DDL 排序，最近截止的排在最前。已实现的目标移至底部，显示"完成于"日期。超过 5 个已实现目标时自动折叠。

**目标详情**：点击目标卡片进入全屏详情页：
- **目标名称**：点击直接编辑
- **DDL**：点击日历图标修改，只能选未来日期
- **目标描述**：多行文本编辑
- **里程碑时间轴**：纵向时间线 + 圆形节点 + 卡片。点击卡片编辑里程碑
- **添加里程碑**：填写任务名称（必填）、具体内容、耗时（小时/天/周）、难点、未来计划
- **实现目标**：点击锁定所有编辑，目标移至已实现列表。已实现的目标双击"该目标已实现"可撤销

### 3.3 打卡栏

**日期导航**：顶部日期栏，左右箭头切换日期，下拉刷新回到今天。

**添加打卡项目**：点击右下角 `+` → 输入项目名称、要求 → 选择打卡周期（每天/每周特定日期）。

**每日打卡**：每个打卡项目以卡片形式展示，左侧项目名+要求，右侧圆形图标：
- 点击 ✓ 表示完成（卡片变淡绿）
- 点击 ✕ 表示放弃（卡片保持灰色）
- 点击已完成/已放弃卡片可撤销（需确认）

**补卡**：左下角"补"按钮仅在当天显示。点击选择已有打卡项目，将其添加到当天打卡列表，名称前标注「补」。

**我的打卡项目**：日期栏下方的入口卡片，全屏展示所有打卡项目。可编辑名称、要求、起始日期、打卡周期。支持暂停/启动打卡。长按可删除项目（打卡记录不删除）。

**时间规则**：打卡仅可在当天操作，过去和未来日期均锁定。未在当天内完成的项目，次日自动视为放弃并同步到日志。

### 3.4 待办栏

**创建待办**：点击右下角 `+` → 输入待办内容 → 可选设置 DDL。

**待办列表**：按月分组，顶部下拉选择月份，默认当前月。每个待办左侧方形勾选框，点击完成（变灰+划线+显示完成时间），再次点击撤销。

**DDL 颜色**：
- 未到期：默认灰色
- 当天到期：橙黄色 🟠
- 已过期：红色 🔴

**编辑/删除**：长按待办卡片 → 弹出底部编辑窗口 → 可修改内容和 DDL，或删除。

**完成折叠**：已完成待办超过 5 项时折叠，只显示最近一条，可展开查看全部。

### 3.5 日志栏

**日期导航**：与打卡栏相同，支持左右箭头和下拉刷新。点击日期文字可弹出日历选择任意日期。

**自动汇总**：每天自动汇总以下数据（按顺序）：
1. 实现的目标
2. 完成的里程碑（显示 `[目标名] 里程碑名` 格式）
3. 打卡记录（✓ 已完成 / ✗ 已放弃，补卡标注「补」）
4. 完成的待办

非当日日志在加载时会自动将未处理的打卡标记为放弃。

**手动笔记**：
- **今天还干了啥**：记录日常收获
- **娱乐项目**：记录休闲活动
- **及时满足型娱乐**：勾选框

所有笔记在当天内可编辑，过期后锁定（只读）。

**手机使用时长**：点击"更新"按钮 → 显示当天屏幕使用总时长 + Top 5 应用及时长。需先在系统设置中开启"使用情况访问权限"。

### 3.6 设置页

右上角齿轮图标进入。

**外观**：
- 主题模式：浅色 / 深色
- 主题颜色：6 种低饱和度预设色 + 自定义色号（长按色块输入 `#XXXXXX` 替换）
- 点击"应用主题"立即生效

**每日提醒**：
- 开关控制是否启用
- 时间选择器（24 小时制）
- 自定义提醒文字
- 保存后系统状态栏弹出通知
- 手机关机重启后自动恢复（BootReceiver）

**数据管理**：
- **导出 SQLite 格式**（换手机用）：分享完整的 `.sqlite` 数据库文件
- **导出 TSV 格式**（数据分析用）：6 张表打包为 ZIP，可用 Excel 打开
- **导入数据**：选择 `.sqlite` 文件 → 红色警告确认覆盖 → 验证文件有效性 → 导入

## 四、进一步开发指南

### 4.1 当前局限性

| 方面 | 局限 | 影响 |
|------|------|------|
| 数据库升级 | 无 Migration 对象 | 任何 Entity 字段变更都需要编写 Migration，否则用户覆盖安装崩溃 |
| 换机迁移 | 无内置迁移向导 | 用户需手动导出 SQLite → 传输 → 新机导入 |
| 数据备份 | 无自动备份 | 卸载 App 数据即丢失，无云同步 |
| AI 辅助 | 未实现 | 目标详情页有预留位置但从未接入 API |
| 分享 | 仅数据导出 | 无法生成可读报告分享到社交平台 |
| 国际化 | 仅中文 | 无英文/多语言支持 |
| 无障碍 | 未适配 | 无 TalkBack 支持，无 contentDescription |
| 平板适配 | 未测试 | 布局在大屏幕上可能拉伸变形 |
| 性能 | 无分页 | 数据量大时 LazyColumn 加载所有数据到内存 |
| Release | 未开启混淆 | APK 体积偏大（~15MB），代码未保护 |

### 4.2 数据库变更步骤

如果未来需要修改数据库结构（加字段、加表、改类型）：

1. 修改 Entity 类
2. 在 `AppDatabase` 中升版本号（如 `version = 11`）
3. 编写 Migration 对象：

```kotlin
val MIGRATION_10_11 = object : Migration(10, 11) {
    override fun migrate(db: SupportSQLiteDatabase) {
        db.execSQL("ALTER TABLE goals ADD COLUMN priority INTEGER DEFAULT 0 NOT NULL")
    }
}
```

4. 在 `databaseBuilder` 链中注册：

```kotlin
Room.databaseBuilder(...)
    .addMigrations(MIGRATION_10_11)
    .build()
```

**不要**在未编写 Migration 的情况下升版本号，否则已安装用户打开 App 直接崩溃。

### 4.3 添加新功能模块

以添加"笔记"模块为例，标准流程：

1. **数据层**：
   - 创建 `NoteEntity.kt`（`@Entity`）
   - 创建 `NoteDao.kt`（`@Dao`）
   - 在 `AppDatabase.kt` 中添加 entity 和 abstract fun

2. **ViewModel 层**：
   - 创建 `NoteViewModel.kt`（继承 `AndroidViewModel`）
   - 通过 `(application as TodoApplication).database.noteDao()` 获取 DAO

3. **UI 层**：
   - 创建 `NoteScreen.kt`（`@Composable`）
   - 在 `GoalListScreen.kt` 的底部导航中添加新 Tab
   - 在 `Screen.kt` 中添加导航目的地（如需要独立页面）

4. **注册**：
   - 如需独立全屏页面，在 `MainActivity.kt` 的 `when` 分支中添加

### 4.4 接入 AI API

目标详情页的"实现路径"区域已预留 AI 辅助生成位置。接入步骤：

1. 添加网络权限和 HTTP 库（如 Retrofit + OkHttp）
2. 创建 API 接口定义
3. 在 `GoalDetailViewModel` 中添加 `suspend fun generatePath(goalName: String): String` 方法
4. 在 `GoalDetailScreen` 中将禁用的"AI 辅助"按钮激活，调用 ViewModel 方法
5. **注意**：一旦添加网络权限，App 不再是纯离线应用，需在隐私政策中说明

### 4.5 代码规范注意事项

- **日期字符串统一**：数据库存储和内部逻辑使用 `yyyy-MM-dd` 格式；界面显示使用 `yyyy/MM/dd` 或 `yyyy年M月d日`。字符串比较依赖此格式，混用会导致排序和过滤错误
- **数据库名**：统一使用 `AppConstants.DATABASE_NAME` 常量（位于 `data/AppConstants.kt`）
- **颜色系统**：所有卡片背景使用 `MaterialTheme.colorScheme.primaryContainer.copy(alpha = 0.25f)`（主题色）或 `surfaceVariant.copy(alpha = 0.4f)`（中性灰），确保浅色/深色模式自适应
- **日期编辑规则**：打卡/日志仅当天可编辑。守卫代码为 `if (_currentDate.value != todayString()) return`

## 六、已知陷阱与经验教训

以下每个条目都是在开发过程中真实遇到并修复过的 bug。了解它们可以避免重复踩坑。

### 6.1 构建系统

| 陷阱 | 现象 | 解决方案 |
|------|------|---------|
| Gradle 自动升级 | IDE/linter 将 Gradle 8.13 升级到 9.6.0，构建报错 | `gradle-wrapper.properties` 中固定 `gradle-8.13-bin.zip`，出现构建错误时优先检查此文件 |
| KSP 版本不匹配 | Kotlin 与 KSP 版本不对应，Room 编译失败 | Kotlin 1.9.24 必须配 KSP 1.9.24-1.0.20。修改 Kotlin 版本时同步修改 KSP 版本 |
| JDK 版本 | JDK 21 可能出现未知兼容问题 | 使用 JDK 17，这是 AGP 8.x 官方支持的版本 |

### 6.2 Room 数据库

| 陷阱 | 现象 | 解决方案 |
|------|------|---------|
| `@Index` 导致崩溃 | 给已有 Entity 添加 `@Index` 注解后，已安装用户打开 App 直接崩溃 | `@Index` 会改变 Room 预期的数据库 schema。添加任何新注解/字段都需要升版本号 + 编写 Migration |
| `fallbackToDestructiveMigration()` | 开发期每次改 Entity 自动删库重建，方便但会丢失用户数据 | **生产版本已移除此调用**。未来任何 schema 变更都必须手写 Migration 对象（详见 4.2 节） |
| Date 存储类型 | 使用 `Long`（时间戳）还是 `String`（格式化日期） | 本项目使用 `Long` 存时间戳 + `String` 存格式化日期（yyyy-MM-dd），后者用于 UI 比较和分组 |

### 6.3 Compose UI

| 陷阱 | 现象 | 解决方案 |
|------|------|---------|
| `readOnly` TextField 不响应点击 | 设为 `readOnly = true` 的 OutlinedTextField 点击无反应 | 其内部消费了点击事件。需在外面包一层 `Box` 并将 `clickable` 放在 Box 上 |
| PullRefreshIndicator 不显示 | 下拉刷新指示器始终不出现 | `PullRefreshIndicator(refreshing = false)` 硬编码为 false。必须用 `remember { mutableStateOf(false) }` 管理状态 |
| 主题切换不生效 | 从设置页返回后主题未更新 | `TodoTheme` 在组合时读取 SharedPreferences。离开设置页后需触发 recomposition。当前方案用 `remember(currentScreen)` 作为 key |
| 卡片 elevation 产生边框 | Card 组件边缘出现不期望的线条 | 设置 `elevation = CardDefaults.cardElevation(defaultElevation = 0.dp)` |
| `remember` vs `rememberSaveable` | 屏幕旋转后输入内容丢失 | 用户在 TextField 中输入的内容用 `rememberSaveable` 而非 `remember`，后者不随 savedInstanceState 保留 |

### 6.4 权限与系统 API

| 陷阱 | 现象 | 解决方案 |
|------|------|---------|
| `QUERY_ALL_PACKAGES` | Google Play 政策审查风险 | 用 `<queries>` 块声明 `MAIN` intent，配合 `getApplicationInfo()` 降级方案 |
| `setExact()` / `setAlarmClock()` | 需用户手动授权或 PendingIntent 类型不匹配 | 最终使用 `AlarmManager.set()`，无需特殊权限，分钟级精度足够 |
| 闹钟重启丢失 | 手机关机后每日提醒不恢复 | 实现 `BootReceiver` 监听 `BOOT_COMPLETED` 广播，重启后重新调度闹钟 |
| `PACKAGE_USAGE_STATS` | 日志页无法读取手机使用时长 | 需用户在系统设置中手动开启"使用情况访问权限"，App 只负责引导 |

### 6.5 逻辑 Bug

| 陷阱 | 现象 | 解决方案 |
|------|------|---------|
| ViewModel 复用不刷新 | 从目标 A 详情跳转到目标 B 详情，显示的目标 A 的内容 | `initialize(id)` 方法有 `if (value == null) return` 守卫，去掉了这个守卫 |
| DDL 日期颜色错乱 | 待办 DDL 颜色与实际到期状态不一致 | 日期比较格式不统一。`formatDate()` 必须在所有比较位置使用同一个 helper |
| 日期编辑规则不一致 | 非当天的日志/打卡可以被编辑 | 统一添加守卫：`if (_currentDate.value != todayString()) return` |
| 打卡超过 5 项折叠的已实现目标 | 已实现目标超过 5 个后自动折叠，只显示第一条 | 这是设计行为，非 bug。折叠逻辑见 `GoalListScreen.kt` |

## 七、设计不变量

以下是**不可违反**的架构规则。每一条背后都有一个曾经踩过的坑。违反任一条都可能引入已知 bug。

### 7.1 数据层

1. **数据库名统一使用常量**：`AppConstants.DATABASE_NAME`（值：`"goal_tracker_database"`），不允许硬编码字符串
2. **日期字符串格式**：内部存储和比较统一用 `yyyy-MM-dd`，界面显示用 `yyyy/MM/dd` 或 `yyyy年M月d日`。字符串比较依赖此格式的正确性
3. **CheckInRecordEntity 不加外键和索引**：该表目前无 `@ForeignKey` 和 `@Index` 注解。添加任一个都会改变 Room schema，需配套版本升级

### 7.2 UI 层

4. **颜色系统仅两级**：
   - 主题色卡片：`primaryContainer.copy(alpha = 0.25f)`
   - 中性灰卡片：`surfaceVariant.copy(alpha = 0.4f)`
   - 不要发明第三级。这保证了浅色/深色模式自适应
   - 红色（过期 DDL）：`Color(0xFFD32F2F)`，橙色（当天到期）：`Color(0xFFFF9800)`
5. **卡片 elevation 始终为 0**：非零值在部分设备上显示异常边框
6. **日期编辑守卫**：打卡和日志仅在当天可编辑。入口处必须有 `if (_currentDate.value != todayString()) return`

### 7.3 架构层

7. **无网络权限**：不声明 `INTERNET`。App 是完全离线的。如果要接入 AI API 或其他网络功能，需在隐私政策中说明
8. **无 DI 框架**：ViewModel 通过 `(application as TodoApplication).database` 获取数据库实例。不要引入 Hilt/Koin
9. **无 Navigation Compose**：导航通过 `sealed class Screen` + `when` 分支实现，回退栈最多一层深度
10. **通知 API 仅用 `set()`**：不用 `setExact()` 或 `setAlarmClock()`。`set()` 不需要用户手动授权 `SCHEDULE_EXACT_ALARM`
11. **ViewModel 继承 `AndroidViewModel`**：所有 ViewModel 统一继承 `AndroidViewModel`，在 `viewModelScope.launch` 中执行数据库操作

### 7.4 何时可以打破不变量

如果新功能确实需要打破以上某项规则（如接入 AI 必须加网络权限），需要：
1. 明确评估影响范围（如加网络权限 → 需要隐私政策）
2. 更新本技术文档中相关章节
3. 如果是 Room schema 变更，必须编写 Migration（见 4.2 节）
